# Domain docs

This repo uses one domain context. Before exploring an area, read the root `CONTEXT.md` and relevant ADRs in `docs/adr/` when they exist. Proceed silently when they do not.

Use terms defined in `CONTEXT.md` in issues, proposals, and tests. Flag conflicts with existing ADRs explicitly.

The domain-modeling skill creates `CONTEXT.md` and ADRs when a term or decision is resolved; this setup does not create empty domain documents.
